Here's the diagnosis:

  Root cause: The component field in MockActionBuilder (line 48).

   /calycopis/Calycopis-broker/github-zrq/java/src/main/java/net/ivoa/calycopis/broker/engine/functional/processing/action/mock/Mo
  ckActionBuilder.java lines 48-48

      private LifecycleComponentEntity component;

  MockActionBuilder is annotated @Embeddable, which means Hibernate tries to map all of its unannotated fields as persistent basic
  columns. LifecycleComponentEntity is a JPA @Entity, not a basic type, so Hibernate fails with "Could not determine recommended
  JdbcType".

  The three @Column fields (prepareActionCount, monitorActionCount, releaseActionCount) are fine — they're long primitives. But
  the component field has no annotation, and Hibernate doesn't know how to store an entity reference as a basic column inside an
  embeddable.

  What component is used for: It's used in the three make*Action methods for:
  1. Logging — this.component.getUuid() and this.component.getClass().getSimpleName()
  2. Passing to new SimpleSleepAction(this.component, ...) — but ComponentProcessingActionBase only extracts the UUID and class
     name from it, so it doesn't hold the entity reference.

  The clean fix (following the project's coding conventions — "passing the required dependency through a method parameter" rather
  than using @Transient + init helpers):

  Remove the component field from MockActionBuilder entirely and pass the component as a method parameter instead. Each calling
  entity already has this available. Would you like me to implement this fix? It would involve:

  1. Removing the component field and the constructor that takes it from MockActionBuilder
  2. Adding a LifecycleComponentEntity component parameter to makePrepareAction(), makeMonitorAction(), and makeReleaseAction()
  3. Updating the 6 entity classes that embed MockActionBuilder to pass this when calling those methods, and removing the this
     argument from the new MockActionBuilder(this) constructor calls
