    Target:

        Experimenting with using shared volumes.
        Configuration files, data files and logs.

    Result:

        In theory we could create directories on the host and then use bind mount volumes.
        But I think we can do everything we need using anonymous volumes.
        The anonymous volumes would be linked to the lifetime of the container.
        Deleting the pod deletes the container, which releases the volumes.

# Asked ChatGPT about creating Podman volumes.

    ?   Is it possible to create a podman volume that mounts a specific directory from the host file system. equivalent to a bind mout volue in the run command

    >   Yes. Podman supports a **named volume backed by a specific host directory**, although for most cases a direct bind mount is simpler.
    >   
    >   For example, your normal bind mount might be:
    >   
    >   ```bash
    >   podman run \
    >       --volume /data/calycopis:/app/data \
    >       myimage
    >   ```
    >   
    >   You can create a named Podman volume that effectively performs the same bind mount:
    >   
    >   ```bash
    >   podman volume create \
    >       --opt type=none \
    >       --opt device=/data/calycopis \
    >       --opt o=bind \
    >       calycopis-data
    >   ```
    >   
    >   Then use it like a normal named volume:
    >   
    >   ```bash
    >   podman run \
    >       --volume calycopis-data:/app/data \
    >       myimage
    >   ```
    >   
    >   You can inspect it with:
    >   
    >   ```bash
    >   podman volume inspect calycopis-data
    >   ```
    >   
    >   You should see options corresponding to:
    >   
    >   ```text
    >   device=/data/calycopis
    >   type=none
    >   o=bind
    >   ```
    >   
    >   ### One important difference
    >   
    >   This is still fundamentally a **bind mount**. Podman isn't copying the data into its normal volume storage. The named volume is essentially a persistent Podman object describing how to mount `/data/calycopis`.
    >   
    >   Consequently:
    >   
    >   ```bash
    >   podman volume rm calycopis-data
    >   ```
    >   
    >   removes the Podman volume definition but **does not delete `/data/calycopis` or its contents**.
    >   
    >   For your use case, this can be quite useful if you want your scripts or pod definitions to deal exclusively in named volumes:
    >   
    >   ```bash
    >   podman volume create \
    >       --opt type=none \
    >       --opt device="${HOST_DATA_DIR}" \
    >       --opt o=bind \
    >       application-data
    >   
    >   podman run \
    >       --volume application-data:/data \
    >       ...
    >   ```
    >   
    >   There are a couple of subtleties around **rootless Podman, SELinux `:Z`/`:z`, ownership and user namespaces** with this type of volume. Given the rootless Podman setup you've been working with, those are worth considering before choosing this over a direct `-v /host:/container:Z` bind mount.

# Re-write the test script to use volumes.
#[user@desktop]

    #
    # We need to use a host file path for the file:// bind mount tests.
    #

    HOST_DATA_DIR=$(mktemp -d)

    podman volume \
        create \
            --opt type=none \
            --opt device="${HOST_DATA_DIR}" \
            --opt o=bind \
            calycopis-data-vol

    podman run \
        -it \
        --rm \
        --volume calycopis-data-vol:/var/calycopis/data:z \
        fedora \
        bash -c '
            date > /var/calycopis/data/datetime
            '

    #
    #  But for the logging and configuration, we can use generic volumes.
    #

    podman volume \
        create \
            calycopis-cfg-vol

    podman volume \
        create \
            calycopis-log-vol

    podman run \
        -it \
        --rm \
        --env "HOST_DATA_DIR=${HOST_DATA_DIR}" \
        --volume calycopis-etc-vol:/etc/calycopis:z \
        --volume calycopis-log-vol:/var/calycopis/log:z \
        --volume calycopis-data-vol:/var/calycopis/data:z \
        fedora \
        bash -c '
            echo "HOST_DATA_DIR [${HOST_DATA_DIR}]"
            date > /etc/calycopis/datetime
            date > /var/calycopis/log/datetime
            date > /var/calycopis/data/datetime
            '

    podman run \
        -it \
        --rm \
        --env "HOST_DATA_DIR=${HOST_DATA_DIR}" \
        --volume calycopis-etc-vol:/etc/calycopis:z \
        --volume calycopis-log-vol:/var/calycopis/log:z \
        --volume calycopis-data-vol:/var/calycopis/data:z \
        fedora \
        bash -c '
            echo "HOST_DATA_DIR [${HOST_DATA_DIR}]"
            cat /etc/calycopis/datetime
            cat /var/calycopis/log/datetime
            cat /var/calycopis/data/datetime
            '


    source "${HOME}/calycopis.env"
    source "${CALYCOPIS_CODE}/bin/versions.sh" "${CALYCOPIS_CODE}/config.yaml"
    source "${CALYCOPIS_CODE}/bin/container-host.sh"

    podman run \
        -it \
        --rm \
        --env "HOST_DATA_DIR=${HOST_DATA_DIR}" \
        --env "CONTAINER_HOST=unix:///run/podman/podman.sock" \
        --volume "${CONTAINER_PATH}:/run/podman/podman.sock:rw,Z" \
        --volume calycopis-etc-vol:/etc/calycopis:z \
        --volume calycopis-log-vol:/var/calycopis/log:z \
        --volume calycopis-data-vol:/var/calycopis/data:z \
        localhost/calycopis/developer-tools:latest \
            bash -c '
                echo "HOST_DATA_DIR [${HOST_DATA_DIR}]"
                podman run \
                    --rm \
                    --volume "${HOST_DATA_DIR}:/var/calycopis/mounted:z" \
                    docker.io/library/alpine:3 \
                    /bin/sh -c "
                        ls -al /var/calycopis/mounted
                        cat /var/calycopis/mounted/datetime
                        "
                '
